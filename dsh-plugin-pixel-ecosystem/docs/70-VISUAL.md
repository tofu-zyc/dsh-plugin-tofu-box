# 70 · 视觉与动画（render）

> 这一份写"看上去是游戏"是怎么做到的：状态怎么变成帧、季节怎么变成材质、大地图怎么在预算内画完。
> 数据契约见 `20-CORE-LOOP.md`；本文只描述渲染侧的消费方式。

## 1. 三条硬前提

1. **不生产美术**。图集只有 idle 2 帧 / walk 4 帧 / run 4 帧（`ATLAS_SLOTS`），新行为靠**姿态变体**表达：
   暂停帧、点头、倾斜、下沉、压缩、抖动、透明。等新美术是无限期任务，姿态变体是当下就能做对的事。
2. **季节是换材质，不是盖滤镜**。草地色阶、树冠调色板、水色、雪覆盖在调色板层重算；
   对整帧刷一层色会与 store 已有的昼夜 wash 叠加，且会把所有物种压成灰。
3. **阴影跟太阳**。同一个世界在清晨和正午必须是两种观感：阴影方向、长度、强度都由 `sunState(world)` 决定，
   地面植物阴影与图集生物阴影共用同一个向量，否则会出现"两个太阳"。

## 2. 状态 → 帧映射表

实现在 `18-sprites.js` 的 `STATE_POSES`，一个 id 一张姿态；`20-render.js` 的 `frameFor`（1px 缓冲）与
`19-atlas.js` 的 `drawAtlasAnimal`（6x 图集）都读它，一处改动两处生效。

姿态字段：

| 字段 | 作用 |
|---|---|
| `role` | 用哪一组帧：`idle` / `walk` / `run` |
| `pause` | 停在第一帧（休息、睡觉、缩团） |
| `speed` | 步频倍率（潜行 0.4、追击 1.2） |
| `nod` | 进食点头幅度（0..1） |
| `tilt` | 前后倾角（度），缓冲层用逐行错位、图集层用旋转 |
| `sink` | 下沉入草的格数 |
| `squash` | 垂直压缩（<1 蹲伏） |
| `shake` | 抖动（受冻、争斗） |
| `alpha` / `shadow` | 透明度 / 阴影倍率（潜伏时阴影缩小） |

当前覆盖的状态（39 个 id）：

| 语义 | id | 观感 |
|---|---|---|
| 站立/警觉 | `idle` `alert` | 呼吸帧；警觉略抬身 |
| 进食 | `graze` `eat` `forage` `browse` | 压扁+点头，身体下沉半格 |
| 埋食 | `bury` | 点头幅度大、蹲低 |
| 饮水 | `drink` | 前倾 7°、下沉 1 格 |
| 休息/睡 | `rest` `sleep` `bask` | 暂停帧；睡更矮更暗且阴影小 |
| 潜伏 | `stalk` `sneak` `ambush` | 低姿慢走/静伏，阴影缩到 55% |
| 捕食 | `hunt` `chase` `strike` `scavenge` | run 帧；前倾、阴影放大 |
| 囤食 | `hoard` `cache` | 慢走 + 小幅点头 |
| 受冻 | `cold` `shiver` `freeze` `huddle` | 抖动/缩团，身体下沉 |
| 移动 | `wander` `explore` `patrol` `walk` `travel` `migrate` | walk 帧 |
| 逃跑/争斗 | `flee` `fight` | run 帧；争斗带抖动 |
| 社交/繁殖 | `court` `socialize` `follow` `mate` `birth` `play` | 慢走/暂停帧 |
| 处理猎物 | `feast` | 蹲身低头点头（`entity.handling === true` 时由渲染侧自动选用） |

**与 behaviour 对齐的最终契约**（2026-11-08 确认）：执行状态机只会产出
`flee / forage / hunt / scavenge / drink / rest / socialize / explore` 这 8 个 id，全部在上表内；
表里其余 id 是给将来状态预留的语义锚点，命中即用、不命中回退。

渲染侧额外消费的两个现有字段：

| 字段 | 用法 |
|---|---|
| `state.phase` | `'approach'`（走向目标）→ 用移动姿态；`'do'`（在目标处执行）→ 用该状态的"低头/蹲伏"循环姿态。`'adopted'` 按 `'do'` 处理 |
| `entity.handling` | `true` = 正在处理猎物/尸体（Holling 处理时间），强制用 `feast`（蹲身低头），不要用追逐姿态 |

两个可选映射（已实现）：`species.ambush` 存在（狗鱼）且 `state.id === 'hunt'` 时，
`approach` 用 `stalk`（慢走低姿）、`do` 用 `strike`（快姿），比全程 run 更像伏击；
`state.id === 'socialize'` 且 `drives.libido > 0.5` 时用 `court`。

**回退规则（重要）**：

1. `animal.state.id` 命中即用；
2. 未命中则按非字母数字切词再查（`eat:grass` → `eat`，`hoard_cache` → `hoard`）；
3. 仍未知 → `idle`；
4. `state` 缺失 → 退回旧的 `animal.intent`；
5. `animal.fleeing === true` 强制 `run`；
6. `pose.role === 'walk'` 且 `animal.running === true` → 升级为 `run`。

未知 id 永远不会崩、不会卡成空白帧 —— 这是"引擎可以先加状态、渲染后补姿势"的前提。
`tests/animation.test.mjs` 逐条钉住了这张表与回退链。

> 待对齐：`state.id` 的最终词表以 behaviour 的 `10b-execution.js` 为准。渲染侧已把上面 38 个 id 的清单发给 behaviour；
> 他们确定词表后，缺的 id 按最接近语义补进 `STATE_POSES`。

## 3. 两条渲染路径

| 路径 | 入口 | 分辨率 | 谁用 |
|---|---|---|---|
| 1px/格 缓冲 | `paintView` / `paintWorld` | 1 像素 = 1 格 | 低缩放（<3x）、`paintWorld` 截图、单元测试 |
| 图集叠层 | `drawDepthLayers` | 真实像素（6x） | 面板主视图（真实美术） |

分层顺序（自下而上）：地面（地形/草/水/雪）→ 植物+生物共用的深度排序叠层 → 尸体 → 阴影 → 足迹/灰尘/涟漪/生效效果 → 雪 → 游标。

## 4. 季节与昼夜

`17-palette.js` 的 `SEASON_LOOK` 给四季各一套：草色双锚点、阔叶四色、针叶四色、水生植物两色、水色六色
（积雪与落叶不在这里，见下面的年份曲线）。
`seasonLook(world)` 每帧返回一个**混合后的 look**，并用 `look.key` 记忆化：

- 季节内部**前 75% 保持本色**，只在最后 25% 过渡到下一季（否则冬季过半就已经"半春"，雪盖在中冬就消失）；
- `world.climate.yearPhase` 优先；没有 climate 时用 `world.time / (DAY_SECONDS × 8)` 兜底；
- 草丛色阶、水色表、雪阈值、树冠精灵都由 look 派生并带缓存，逐格循环里没有季节运算。

**物候（积雪与落叶）是年份曲线，不是每季一个常数**。早先用「冬季 snow=1、bare=1」，
结果全年 1/8 都是一片白、树全灰，看着像雪灾。现在用两条控制点曲线（`SNOW_PROFILE` / `BARE_PROFILE`）：

| yearPhase | 0.00 春 | 0.30 夏 | 0.58 夏末 | 0.70 秋末 | 0.76 | 0.80 | **0.82–0.86 深冬** | 0.89 | 0.93 | 0.97 | 1.00 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 积雪 | 0.03 | 0 | 0 | 0.18 | 0.45 | 0.74 | **1.0（只占全年 4%）** | 0.6 | 0.3 | 0.12 | 0.03 |
| 落叶 | 0.08 | 0 | 0.02 | 0.35 | 0.72 | 0.96 | **1.0** | 1.0 | 0.88 | 0.45 | 0.08 |

积雪不是二值抖动：按 2 个低频正弦场（≈33 / 55 格）+ 一个中频场的叠加做**连续掺白**，
所以 6x 下是"雪堆"而不是棋盘格；掺白上限留在 0.9 左右，地面结构始终能透出来。

四季的可见差别：

| 季节 | 地面 | 树冠 | 水 | 其他 |
|---|---|---|---|---|
| 春 | 嫩绿 | 亮绿 | 亮青蓝 | 残雪痕迹 |
| 夏 | 深绿紧实 | 深绿 | 深青 | 无雪 |
| 秋 | 枯黄 | 橙红、按 id 分批落叶 | 偏橄榄 | 初雪薄斑 |
| 冬 | 灰黄 + 积雪堆 | 常绿针叶 + 落叶枯枝骨架 | 冷白蓝 + 近岸结冰 | 落雪粒子、芦苇/枯枝露出雪面 |

**水按深度分层，不按水草分层**。水草只长在浅水：`weedDepth = d<0.16 ? 1 : 1-(d-0.16)*1.8`，所以就算水草场饱和，
湖心也仍然是蓝的（之前整片湖被染成薄荷绿池塘）。深度色阶也提前了：`mid` 从 d≈0.04 开始掺、`deep` 从 d≈0.22 开始掺，
浅水绿、中水青、深水蓝三段读得出来。

**岸线泡沫是渐变带，不是 1px 描边**。泡深按深度分四档（0.8 / 0.56 / 0.32 / 0.15），并且三个抖动明暗各自乘不同的
系数（0.66 / 0.92 / 0.5）—— 于是泡沫环在格子级被"打断"，再被后画的水草/芦苇/睡莲覆盖，不会像贴纸描边。

**树不再是一个模子**。每株植物用自己的 id 决定：

- 剪影：`TREE_SHAPES` 五种（圆冠 / 高冠 / 宽冠 / 歪脖 / 尖塔），`plant.id % 5` 选；
- 物候：`plant.id % 7 < 2` 为常绿（`CONIFER_SHAPES` 三种：冷杉 / 云杉 / 松），冬天照样是深绿针叶，树顶带雪；
- 落叶按 `look.bare > (id % 7) / 7` 分批：秋天的森林是"有的还满叶、有的已经光秃"，不会同一帧全秃；
- 枯枝是专门的骨架渲染（树干 + 四条上扬分枝），不是把树冠打洞——打洞会变成灰环。

灌木三种剪影、芦苇按 id 摆动、睡莲两型（冬季结冰后花不画、叶片整体转白）。

### look 键（稳定契约）

`seasonLook(world)` 返回的 `look.key` 是**可依赖的稳定键**，定义如下：

- `index = min(3, floor(yearPhase * 4))` —— 0=春 1=夏 2=秋 3=冬（`SEASON_IDS` 顺序）；
- `step = round((yearPhase * 4 - index) * SEASON_STEPS)`，`SEASON_STEPS = 16`，所以 `step ∈ 0..16`；
- `key = index * 17 + step`，取值 0..67；解码：`index = floor(key / 17)`、`step = key % 17`。
- `plantKey = index * 9 + round(local * 8)`（0..35），只用于植物精灵重建（更粗，避免频繁重建）。

约束：`yearPhase` 相同 → `key` 相同 → 逐像素相同（有测试钉住）；一帧内画两个不同年份的世界不会互相污染
（memo 是 8 项的 Map，不是单槽）。测试请断言"同一 yearPhase 同键"和"键到 (index, step) 的换算"，
不要断言某个具体数字序列——`SEASON_STEPS` 将来若变大，`key` 的取值范围会跟着变。

昼夜：面板层已有的 wash 继续负责整体明暗与晨昏暖色（`21-store.js`），渲染层只负责**光照方向**：
`sunState(world)` 由 `dayPhase` 推出方位角与高度角 → 阴影偏移 `shadowOffset(world)`（横向摆动 + 晨昏拉长）
与强度（正午最实、夜里几乎不画）。

## 5. 大地图性能（实测）

环境：Windows / Node v26.2.0，`paintView` 单帧中位耗时（缓冲路径，纯 CPU）。

**真实世界**（`createWorld` 默认 1024×640，seed 12345 跑 40 s 仿真后：524 生物 / 1497 植物 / 21 尸体）：

| 场景 | 中位 | p95 |
|---|---|---|
| 全图 1024×640，全部图层 | **15.2 ms** | 38.1 |
| 全图，仅地面 | 12.3 ms | 13.4 |
| 6x 视口 176×110 格（1056×660 px） | **0.53 ms** | 0.96 |
| 6x 视口 + 额外 600 只密集兽群（共 1058 生物） | 0.78 ms | 1.25 |
| 全图，冬季（积雪 + 秃树 + 冰缘 + 落雪） | 20.5 ms | 35.5 |
| 6x 视口，冬季 | 1.03 ms | 1.16 |

该视口内可见 **40 只生物 / 77 株植物**（密集兽群时约 640 只生物）。
（多次运行的波动约 ±10%；全图 p95 会碰到 33 ms 线，6x 视口任何时候都在 1.5 ms 以内。）

**合成压力世界**（3000 生物 + 1150 植物 + 260 尸体，改动前后对比）：

| 场景 | 改前 | 改后 |
|---|---|---|
| 1024×640 全图，全部图层 | 43.1 ms | **17.4 ms** |
| 1024×640 全图，仅地面 | 38.8 ms | 15.0 ms |
| 1024×640 全图，冬季 | — | 21.2 ms |
| 640×400 全图，全部图层 | — | 8.3 ms |
| 6x 视口 176×110 格 | 3.2 ms | 1.18 ms |
| 3x 视口 320×200 格 | — | 3.24 ms |

结论：**最坏情况（整张 1024×640 地图一次画进一个缓冲）15.2 ms ≈ 66 fps、冬季 20.5 ms ≈ 49 fps**，都高于 30 fps 门禁；
玩家实际看到的 6x 视口是 0.6–1.1 ms，渲染不构成瓶颈。拆层（全图）：地面 18.9 / 植物 +0.3 / 动物 +0.4 / 雪 +0.3。

做法（都是"省掉逐格的颜色运算"，不是降画质）：

1. **草**：16 个覆盖档 × 32 个亮度增量预编译成 `GRASS_LUT`，逐格只剩一次数组读；三个尺度（风摆 / 团块 / 慢斑块）
   的扰动在循环外预计算成"每列/每行一个系数"，逐格只有两次乘加（曾经用 `Math.round(双精度乘积)`，光这一处就吃掉 7 ms）；
2. **草地大尺度斑块**：`sin(x·a)·sin(y·b)` 可分离 → 两条一维正弦表，省掉每格 2 次 `Math.sin`；
3. **水**：深度 128 档 × 3 个抖动明暗预编译，焦散再按 17 档亮度预混合；三道行波的 `sin(A+B)` 用行列正弦表拆成 2 乘 1 加；
4. **阴影**：由"外接矩形逐像素判定椭圆"改成**行跨度**（每行一段连续像素 + 定点整数调光），
   同像素数从 18 ms 降到 2 ms —— 这是全图帧率翻倍的关键；
5. **积雪**：不做"白色 / 草色"二值抖动（在 6x 下会印成棋盘格），而是按 2×2 块噪声做**定点整数混色**，
   覆盖度连续变化；这一步单独用 `blendColor` 版本时要多花 13 ms，改成整数混色后降到 3 ms 内；
6. **排序**：植物/生物的深度排序用复用的索引数组，不再每帧给每只生物分配 `{animal,x,y}` 对象（GC 抖动来源）。

## 6. 细节与预算

| 细节 | 上限 | 说明 |
|---|---|---|
| 生物落地阴影 | 每只 1 个椭圆 | 半径随体型（`STAGE_SCALE`）与姿态缩放；水生动物改画水面涟漪 |
| 植物阴影 | 每株 1 个椭圆 | 方向/长度/强度跟随太阳；夜间不画 |
| 足迹拖影 | 移动中的生物各 1 格 | 原有图层，颜色由 `TRAIL_COLORS` 决定 |
| 足底灰尘 | 400 次/帧（仅近景） | 每步一次脉冲（步态相位前 1/8），全图/远景自动关闭 |
| 水面涟漪 | 随效果数量 | 只在水格上画出扩散环；判定用该格地形，不需要引擎新增字段 |
| 落雪 | 240 粒/帧（仅冬季） | 位置 = 抖动哈希 + tick，同 tick 结果完全一致 |

"近景"判定：视图 ≤ 48,000 格（约 220×220）才开灰尘；雪按季节自动开。

## 8. 还需要别的 scope 配合的事

1. **Lead**：`27-registration.js` 目前只导出 `frameFor`。建议补导出 `poseFor` / `STATE_POSES` / `seasonLook` /
   `sunState` / `drawDepthLayers` / `ensureAtlas`，这样图集路径与季节混合也能被单测直接钉住（现在只能从像素反推）。
2. **ui**：`21-store.js` 的昼夜 wash 与季节材质不冲突，保持现状即可；若要让检视器显示"季节/日出日落"，
   `dayPhaseOf` / `yearPhaseOf` 已在闭包里可用。
3. **behaviour**：已对齐（8 个 id + `state.phase` + `entity.handling`，见 §2）。
   进度 0..1 由 `state.since/until` 现算，渲染侧目前用时间驱动点头/抖动；若以后需要"越接近完成越急躁"之类的效果，
   直接读这两个字段即可，不需要新字段。
4. **sim-core**：`world.climate.yearPhase/dayPhase` 一旦落地，渲染自动改用它（现在有 time 兜底），
   另外地图放大到 1024×640 后需要复测本文 §5 的数字（`createWorld` 目前仍夹到 512）。
