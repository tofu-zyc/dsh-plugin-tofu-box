# 00 · 设计圣经（Pixel Terrarium）

> 这份文件定义"做成什么样算成功"，不定义怎么实现。实现细节在 10/20/30/40 号文档里。

## 一句话

一个**看得懂的活世界**：玩家不看数字也能说出一只动物此刻在做什么、为什么，以及它昨天为什么死了。

## 三条产品原则

1. **现象必须可见、可解释。** 任何一个死亡、迁徙、数量崩盘，玩家都要能在面板里查到因果（能量收支、被捕食、饿死、冻死）。隐藏的数学等于不存在。
2. **数字从物理推出，不从平衡推出。** 全局手调量只允许存在四个：格距、日内秒数、年天数、产能系数 `κ`。其余全部由体重、温度、地形、性状推出。想要"更多兔子的存活率"，不能调兔子，要调世界。
3. **行为必须有时间和地点。** 一个动作要有持续时长、有发生地、有完成/失败条件。没有这三样，屏幕上就只有反应场，没有生物。

## "看起来像个游戏" 验收清单

任何一版交给玩家看之前，逐条检查：

| # | 标准 | 检验方法 |
|---|---|---|
| G1 | 30 秒内知道能干什么 | 首次进入有引导提示；不读文档能点出"放一只兔子" |
| G2 | 点任何一只动物，能看到它在干什么、为什么 | 检视器显示：状态、剩余时长、驱动力条、目标、最近一次决策的理由 |
| G3 | 世界有节律 | 昼夜和季节变化可辨；同一块地在不同时段观感不同 |
| G4 | 每秒都有可看的事件 | 事件条（捕食/出生/死亡/迁徙/囤食）；镜头跟随有内容 |
| G5 | 失败可解释 | 物种灭绝时，面板能给出主要死因与时间线 |
| G6 | 视觉统一且有层次 | 像素风一致；地面/植被/生物/粒子分层；有阴影、有景深、有反馈 |
| G7 | 操作有反馈 | 每次笔刷、每次投放都有粒子/音效级反馈与撤销路径 |

## 明确不做

- 不做学术精度的能量学。我们只借它的**比例关系**（10% 营养级、3/4 代谢指数、20–50%/80% 同化率、Q10≈2.5），绝对值由 `κ` 吸收。
- 不做玩家看不见的隐藏系统。每个新机制必须先在检视器/面板里有对应的可读输出。
- 不做"调参式平衡"。如果某个物种活不下去，先问"它缺的那个环在哪"，而不是改它的 `meatGain`。

## 与旧版的关系

0.2.x 是"用数值堆出稳定种群曲线"的实验台。0.3 起改用能量账本 + 决策状态机，旧的世界存档不兼容（`SAVE_VERSION 2`）。旧文档 README/DESIGN/HANDOVER 描述的是 0.2.x，以本目录为准的部分会在 `90-ROADMAP.md` 里标注。
