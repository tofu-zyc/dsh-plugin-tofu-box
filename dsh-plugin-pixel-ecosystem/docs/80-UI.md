# 80 · 界面与可读性（P4）

> 这份文档说明面板**为什么长这样**、每个数字**从哪来**，以及哪些字段还在等引擎。
> 目标是 `00-VISION.md` 的一句话："玩家不看数字也能说出一只动物此刻在做什么、为什么，以及它昨天为什么死了。"

## 1. 验收对照（G1–G7）

| # | 标准 | 这一版的落地 |
|---|---|---|
| G1 | 30 秒内知道能干什么 | 首次进入在画布上方弹三步引导（选物种 → 点到草地 → 点动物看它）；默认页签就是"工具"，不翻页就能放兔子；引导可"重新看" |
| G2 | 点任何一只能看到在干什么、为什么 | 检视器 v2：状态+阶段+剩余时长+下次决策、8 条驱动力条、目标点与距离、计划、最近一次决策（选了什么、赢了多少分、败给了谁、为什么） |
| G3 | 世界有节律 | 顶栏显示第几天 / 时钟 / 温度；渲染层负责昼夜与季节观感 |
| G4 | 每秒都有可看的事件 | 画布下方常驻事件条：捕食/出生/死亡/迁入/囤食/投放，带物种图标、数量、坐标、几秒前；点一下镜头飞过去 |
| G5 | 失败可解释 | 物种表有死因分解条（被捕食/饿死/冻死/受伤/老死/不明）；活着的动物显示**预测死因**；读档失败与旧版存档都会**说出来**，不是静默重开 |
| G6 | 视觉统一且有层次 | 物种图标（每种一个像素 glyph）在调色板、检视器、物种表、事件条四处一致；侧栏三色阶统一 |
| G7 | 操作有反馈 | 笔刷脚印预览圈 + HUD 实时显示笔刷/格子坐标 + 放置/失败/擦除 toast。**撤销路径未做**（见第 9 节） |

### 视口操作（不要"顺手改方向"）

| 操作 | 行为 |
|---|---|
| 滚轮**上** | 放大（一格一档，5× → 6× …） |
| 滚轮**下** | 缩小，最小到 **1×**（1 像素 = 1 格，用来看整张图，不是错误状态） |
| HUD 左下 `− N× +` | 显式缩放按钮，方向和滚轮一致；手感不对时用它兜底 |
| `+` / `-` 键 | 同上 |
| 「适应窗口」/ `F` | 缩放到能装下整张地图 |

> 滚轮方向被改错过两次（都是"我觉得反了"式的猜测）。**这一列的方向以玩家实测为准**：上=放大。
> `.pe-hud` 整体是 `pointer-events:none`，所以 HUD 里的按钮必须单独 `pointer-events:auto`，否则点不动。
> 面板内任何新按钮都要加进 `STAGE_CONTROLS` 豁免表，否则会被舞台的 `pointerdown` 吃掉点击。

## 2. 布局

```
┌────────────────────────── pe-head ─────────────────────────────┐
│ 标题 · 第N天 时钟 温度 │ 存活脉冲 · 遗骸 │ 11 个物种计数 │ 控制按钮 │
├──────────────────────────────────────────┬─────────────────────┤
│                                          │ [工具][物种][能量流] │
│                pe-stage                  ├─────────────────────┤
│   canvas + HUD + 小地图 + 引导/空态/读档提示 │  页签内容（滚动）    │
│                                          │                     │
├──────────────────────────────────────────┤                     │
│ pe-eventbar  事件  筛选   事件条（横向滚动）  ├─────────────────────┤
│                                          │ pe-dock 检视器（常驻）│
└──────────────────────────────────────────┴─────────────────────┘
```

三条设计约束：

1. **工具默认在前**：G1 比"信息密度"重要，放生物不该翻页。
2. **检视器常驻**（pe-dock），不随页签消失：点动物立刻有回应。
3. **三个页签全部挂载、只用 CSS 隐藏**：这样渲染测试能覆盖每一个面板，而不是只测当前页签。

## 3. 检视器 v2：每个字段的来源

| 显示 | 字段 | 来源 | 缺失时的行为 |
|---|---|---|---|
| 年龄 | `entity.age` | 引擎 | — |
| 储能 | `body.E` / `body.Emax`（kJ） | sim-core 09b | 回退 `entity.energy` + `balance.maxEnergy` |
| 体量 | `body.V`（kg 湿重） | sim-core | 回退 `genes.size`，单位标为基因值而非 kg |
| 成熟度 | `body.M` | sim-core | 回退 `age / balance.maturity` |
| 健康 / 疲劳 | `body.health` / `body.fatigue` | sim-core | 健康显示 "—"；疲劳回退 `needs.energy` |
| 8 条驱动力 | `entity.drives{hunger,thirst,cold,fatigue,fear,social,curiosity,libido}` | behaviour 09-needs | 全部按 `20-CORE-LOOP.md` 2.2 从身体/需求派生，标题标"由身体推导" |
| 状态 / 阶段 | `entity.state.{id,phase}` | behaviour 10-decide / 10b | 回退 `entity.intent` |
| 剩余时长 | `state.until - world.time` | behaviour | 显示 "—" |
| 下次决策 | `entity.thinkTimer` | 引擎 | 显示 "—" |
| 目标点 | `entity.targetX/Y` | 引擎 | 显示 "—" |
| 计划 | `entity.plan.steps[0]` | behaviour | 显示 "—" |
| 决策理由 | `entity.decision{at,picked,why,score,alternatives}` | behaviour | 回退"最响的驱动力"，并标注这是派生 |
| 预测死因 | 由驱动力+年龄+附近掠食者推算 | 本面板 | 没有风险时显示"暂无风险" |

"为什么"那一行读起来是：**最近决策 · 因为 疲劳**，下面小字是它击败的备选（`胜过 探索 0.11`）。这是把
`00-VISION.md` 原则 2 变成可读：玩家看到的是"它累了所以去睡"，不是一条分数曲线。

## 4. 死因：精确与推断

引擎的 `dieOf()` 会把 `body.cause` 写到尸体上（`corpse.cause`），所以：

* **精确**：动物消失的同一轮观测里看到它的尸体 → 直接用尸体的 cause。当前实测 **57/66 ≈ 86% 是精确的**。
* **推断**：尸体被食腐者吃掉、或旧路径没写 cause 时，按下面的顺序推断，并在物种表面板标题标
  `死因 · 推断 N`，让玩家知道哪些是猜的。

推断顺序（先解释"能量耗尽"，再解释"被吃"）：

1. 附近（≤4.5 格）有以它为猎物的掠食者 → `predation`
2. 储能 ≤ 2% 上限 → `starved`（这就是引擎的死亡条件）
3. 年龄 ≥ 寿命 × 0.92 → `old`
4. 寒冷 ≥ 0.6 → `frozen`
5. 健康 ≤ 0.2 → `injury`
6. 否则 `unknown`（诚实的桶，不猜）

## 5. 事件条：四类事件的判定

| 事件 | 判定 | 备注 |
|---|---|---|
| 投放 `placed` | 笔刷前后 `world.nextId` 水位差 | 100% 精确，玩家自己干的事 |
| 出生 `birth` | 新 id，且 4 格内已有同种成体 | 同窝个体会被聚合成一条（×N） |
| 迁入 `migration` | 新 id，且 `world.lastImmigration.species` 匹配、时间差 ≤ 2s | 引擎的补充种群事件 |
| 死亡 `death` | 上一轮观测有、这一轮没有 | 带 count 与死因 |
| 捕食 `predation` | 死亡且 cause = predation | 一轮最多单列 3 条，其余并入 death |
| 囤食 `hoard` | `world.caches[].energy` 上升 | P5 之前不会出现，代码已就位 |

事件保留 150 游戏秒、最多 64 条；条上显示数量、坐标和相对时间。**点击 = 飞过去**（`lookAt`），
若受事动物还活着则同时选中它——事件条因此不只是日志，是"去看现场"的入口。

## 6. 能量流面板：口径

单位统一为 **kJ / 游戏日**（`10-SCALE-AND-UNITS.md` 2 节：不要用每秒写速率）。

| 条 | 值 | 来源 |
|---|---|---|
| 阳光 → 净初级生产 | `Δworld.budget.gpp / Δt × DAY_SECONDS` | 引擎 13-fields 自己累计的 GPP |
| 植物 → 草食 | `Σ 草食种 ΔΣE × DAY_SECONDS/Δt + 呼吸` | 观测：储能变化 + 维持功率 |
| 草食 → 肉食 | 同上，肉食/食腐种 | 同上 |
| 动物呼吸 | `Δworld.budget.animalRespired`（无则 Σ pMetabolism） | 引擎 09b |
| 植物呼吸 | `Δworld.budget.plantRespired` | 引擎 13-fields |
| 现存 | 植物：`Σ grass·CELL_AREA·GRASS_ENERGY`（每 8 格采样 1 格）；动物：Σ body.E | 观测 |

每物种收支表：吸收（≥0）、呼吸、净变化（带符号）。净变化为负 = 这个物种正在吃储备。

**当前实测（seed 默认，113 游戏秒）**：GPP 4.23e8、植物呼吸 3.96e9、现存植物 1.41e10 kJ，
动物呼吸 1.49e6、草食吸收 7.0e5 kJ/日。植物呼吸比 GPP 大一个量级 → 草地正在被快速抽干，
动物的呼吸也大于摄入。面板如实显示，这正是它存在的意义：**数学第一次变得可看**（见第 8 节待办）。

## 7. 引导、空态与错误态

* **首次引导**：三步，存 `dsh-pixel-ecosystem:onboarded`；帮助弹窗里可"重新看引导"。
* **空世界**：画布中央一张卡说明"这个世界安静了" + 补充生物按钮（走玩家自己的放置路径，因此也进事件条）。
* **正在读取世界**：`snapshot.loading === true`（只有解压存档这一条路径会出现）时显示"正在读取世界…"，
  而不是把"还没读完"画成"世界是空的"。
* **读档失败**：黄色提示卡按错误码给三种不同说法，技术原因放在 tooltip 里：
  | code | 含义 | 文案键 |
  |---|---|---|
  | `unsupported_version` | 存档版本不兼容 | `notice.unsupportedVersion` |
  | `corrupt` | 存档损坏/截断 | `notice.corrupt` |
  | `no_decompressor` | 宿主不支持解压 | `notice.noDecompressor` |
  | legacy（无 code） | 只有旧版 v1 键 | `notice.legacyBody` |
* **旧版存档**：明确说明"0.3 格式不兼容，已开新世界，旧存档原样保留"，并且**不写、不删**旧键。

## 7.4 画布尺寸不变式（P0，0.3.9）

曾经出现过"地图只在面板左上角画一小块、其余全黑、HUD 显示 5×"的故障。根因是**画布有两套尺寸在互相猜**：

| 概念 | 谁决定 | 值 |
|---|---|---|
| backing store（`canvas.width/height`，绘画目标） | `draw()` 独占 | `view.width × view.scale` |
| CSS 盒（玩家看到的矩形） | `draw()` 独占，来源是 `view.cssWidth/cssHeight`（= stage 尺寸） | `stage.width × stage.height` |
| 每格像素（点击换算） | `view.pxPerCellX/Y` = `cssWidth / view.width` | 与 `scale` 有 ≤1% 差异 |

三条不变式，任何一条破了就会出现那个 bug：

1. **backing store = view.width × scale**，与 CSS 盒**解耦**。所以缺少放大画布（offscreen）时，
   CSS 会把 1:1 的画面放大填满盒子，而不是只剩 1/scale 大小。
2. **buffers 不依赖 world**：`ensureBuffers()` / `ensureDrawBuffers()` 只要"有 2D context + 非零 view"就补齐
   `imageData` 与 `offscreen`。暖启动（有存档、异步解包）时面板会先 mount、world 还是 null，
   这条路径过去会跳过全部 buffer 创建 —— 这就是"刷新时好时坏、重启服务必现"的来源。
3. **绘制的前置条件由绘制自己保证**：`draw()` 第一件事就是 `ensureDrawBuffers()`，不是靠 `attach()`。

配套布局：`.pe-stage{position:relative;flex:1}` 必须是 `.pe-stagewrap` 的 flex 子项（**不要**用
`position:absolute;inset:0`：那会让画布盖住事件条，实测 bar.y 与 stage.y 相同）。

验证（真浏览器）：

```powershell
node tests/panel-layout.mjs --url "<panel url>"    # 冷启动 / 切回 / 改窗口 / 隐藏显示 四格
node tools/ui-smoke.mjs --url "<url>" --corners    # 画布四角点击 → 读 HUD 格子号
```

判据（与 `tests/panel-layout.mjs` 实际判据一致，见 `97-PROBES.md` §4.5）：`|stage.w - canvas.w| ≤ 4`、
`|stage.h - canvas.h| ≤ 4`（`.pe-stage` 自带 2px 边框，两侧共 4px，所以不能要求 0）、`paint ≥ 0.5`（采样非黑占比），
四角点击的格子号与期望误差 ≤ 1 格。`window.__peDebug()` 是给这两个工具只读诊断用的接口。

## 7.5 存档：同步建世界、异步压缩写盘

`packWorld()` 会把整张图压成 gzip + base64，实测 1024×640 / 483 实体：

| 指标 | 数值 |
|---|---|
| 裸 JSON | 4.99 M 字符 |
| gzip 后 | 1.63 MB → base64 **2.18 M 字符**（进得去 5 MB 限额） |
| 打包耗时 | 110–124 ms |
| 解包 + 反序列化 | 30–129 ms |

因此 store 的分工是：

* **没有存档时同步建世界**：`createStore({storage:null}).ensureWorld()`、scene-lab、测试都要求"立刻给我世界"，
  这条路径没有异步理由，所以是同步的。`ensureWorld()` 仍返回世界对象。
* **只有真有存档时才是异步**：此时 `ensureWorld()` 返回 `null`、快照带 `loading: true`，面板显示"正在读取世界…"；
  `whenReady()` 是正式入口，测试与集成都用它 await。
* **写盘不阻塞帧**：`save()` 在微任务里 `packWorld` → `setItem`，带重入保护；世界被替换（新世界）时用
  `worldToken` 丢弃过期的写入。`saveNow()` 是同一个压缩保存的 awaitable 别名。
* **关页面是最后手段**：`beforeunload` 只能同步，所以走 `saveSync()`（未压缩、低精度打包）。它在满图上会超限额，
  因此只是兜底；真正的保证来自"每 30 游戏秒自动存 + 标签页隐藏时立刻存"。
* **顶栏存档药丸**：`存档 {size}` 用引擎的 `formatSaveSize()`；保存中显示"保存中…"，写不进存储时变黄并显示
  "存不进本地存储"。读档成功后也会立刻显示已有存档大小。

## 8. 还需要引擎提供的字段（按优先级）

1. **`world.deathLog`**：环形缓冲 64 条 `{species, cause, at, x, y}`。现在死因靠"尸体命中"，
   尸体被吃掉就只能推断（实测 14% 走推断）。有日志就是 100% 精确，且能给出"灭绝时间线"（G5 的完整版）。
2. **结构化事件流 `world.events`**：`{kind, species, x, y, count, at, cause}`。现在出生/迁入靠位置邻近
   与 `lastImmigration` 猜，且一轮观测内的多次事件会被聚合成一条、坐标只取同种第一只。
3. **每物种能量收支的引擎侧账本**（摄入/同化/呼吸/繁殖/排泄，按 `20-CORE-LOOP.md` 不变式 2）。
   现在摄入用"储能变化 + 维持功率"反推，跨观测间隔的繁殖与尸体转移会混进来。
4. **`world.budget` 的标定复核**：`gpp` 与 `plantRespired` 差一个量级（见第 6 节），需要 sim-core 确认
   是切片累计口径问题还是产能常数问题。面板不会掩盖它。
5. 昼夜/季节文案（`climate.season`）：13b 落地后顶栏可以直接显示季节名。

## 9. 已知未做

* **撤销路径**（G7 后半）：笔刷与投放不可撤销。需要的不是 UI，而是 `14-player-tools.js` 记录每次笔刷的
  改动集（格坐标 + 旧值/新 id），UI 只负责提供一个"撤销上一步"按钮。属于 lead scope。
* 音效/粒子级反馈：粒子由渲染层的 `spawnEffect` 负责，UI 只做脚印预览与 toast。
* 逐条精确事件（见第 8 节第 2 条）。
* 移动端窄屏只做了两档断点（980/760px），未在真机验证。

## 10. 怎么验证

```powershell
cd dsh-plugin-pixel-ecosystem
node tools/build-client.mjs
node --test tests/client.test.mjs      # 24 个用例，覆盖面板结构/字典/CSS/存档提示
```

关键用例（改 UI 时必看）：

* `every key the panels render exists in both dictionaries, and no key is dead` —— 字典双向一致，且没有死键。
* `every CSS selector is pe- prefixed` —— 顺便禁止 CSS 注释（会被当成选择器）。
* `the inspector shows the eight drives, the state clock and the decision record`
* `the event ticker reports what the player did, and a click flies there`
* `the energy panel draws the four-stage cascade once the world runs`
* `the store writes a v2 save under the documented key and round-trips it` —— 压缩写盘、`gz:` 前缀、能进 5 MB 限额
* `a legacy save is reported once and left untouched`
* `a corrupt save reports why instead of starting over silently` / `a save from another format says so instead of "corrupt"`
