# 40 · 行为系统（P2：感知 / 驱动力 / 审议 / 执行）

> 这份文档写给三类读者：想知道"动物为什么动"的玩家向设计者、要改 decision 的工程师、
> 以及要给渲染/检视器接字段的同事。契约字段以 `docs/20-CORE-LOOP.md` 为准，本文解释**为什么**。

## 1. 一句话

0.2.x 的动物是"反应场"：每 0.22–0.55 秒把全部意图重掷一次，意图没有时长，感知是 12 次随机抽样，
决策从不读身体。现在每一只动物都是**一个有账本、有记忆、有承诺的状态机**：

- 它只看见**真的扫过**的地方（规则栅格扫描，不是随机抽样），并把结果带时间戳记下来；
- 它想做什么，由**身体状态导出**的八个驱动力算分决定（hunger = 1 − E/Emax）；
- 一旦开始做一件事，就有**计划时长 + 完成条件 + 最小承诺**，中途只有"要命的事"能打断；
- 它记得哪块地喂过它、哪儿差点吃了它，记得的东西会衰减，也会被"再访"加强。

## 2. 每 tick 的顺序（顺序是设计的一部分）

```
stepEntities (13-fields)
└─ 每只：metabolise            ← 09b，唯一的能量出口
   └─ stepEntity (12-step-entity)
      ├─ decayNeeds            ← 09：只扣账本类通道（口渴）
      ├─ updateDrives          ← 09：从 body 导出 8 个驱动力
      ├─ perceive              ← 08b：错峰 ~1Hz 真实扫描 → belief
      ├─ decide                ← 10：只在状态边界 / 中断时打分
      ├─ execute               ← 10b：推进状态、瞄准、判定完成
      ├─ feed                  ← 11：Holling II 摄食（sim-core）
      ├─ moveToward + gait     ← 08/12
      └─ updateFatigue         ← 09（有 body 时由 09b 负责）
```

**为什么感知在决策之前**：决策必须读"这一 tick 的"身体和眼前。旧版决策读的是自己涨的计时器，
所以会出现"站在草地上饿死"。

## 3. 感知与信念（08b-perception.js + 07-spatial.js）

- **真实扫描**：`scanFlora` 在视野圆内按步长遍历（半径 >8 时步长 2，模拟"边缘看不清"），
  逐格检查地形、`canStand`（涉禽不能站深水、鱼不能上岸）、存量与危险记忆热度。没有随机抽样。
  成本：一只动物一次扫描约 50–200 格，1Hz 错峰，1000 只 ≈ 每 tick 十几只扫描。
- **错峰**：每只动物的下一次扫描时间在 `[0, 1s)` 内由世界 RNG 随机初始化，不会整群同 tick 抖动。
- **信念带时间戳会过期**（`belief.*.t`）：

  | 通道 | 内容 | 存活 |
  |---|---|---|
  | `belief.food` | 最好的可食点（含质量、来源 kind: flora/foliage/prey/memory） | 35 s |
  | `belief.carrion` | 最近尸体 | 25 s |
  | `belief.threat` | 视野内捕食者 | 6 s |
  | `belief.water` | 可站立的饮水点（**岸边格**，不是水心格） | 70 s |
  | `belief.home` | 最近一次休息的地点（家域锚点） | 不失效 |
  | `belief.caches` | 自己的屯粮点（`world.caches`，P5） | 每次扫描刷新 |
  | `belief.sites` | 记忆中的采食点（最多 4 个） | 120 s |
  | `belief.marks` | 记忆中的危险点（最多 3 个） | 60 s |

- **记忆增强/衰减**：`rememberFood` 对 6 格内的已知点做"再访加强"（`0.55·旧 + 0.65·新`），
  新点入场；满了就淘汰"价值 − 年龄"最差的那个。危险记忆以 `threatHeat` 的形式降低附近采食点的吸引力。
- **方向性偏好**：`recallFood` 对**身后**的记忆点打折（0.12×(1−cos)）。动物是往前找食的，
  一个总把动物拉回原地的记忆会把它变成随机游走。
- **饮水点必须是岸边可站立格**：这是"喝水跑步机"的根因修复——瞄湖心永远到不了 → 放弃 → 再决定。

## 4. 驱动力（09-needs.js）

八个通道，全部**导出**，没有一个是计时器：

| 驱动 | 来源 | 说明 |
|---|---|---|
| `hunger` | `1 − E/Emax`，带 12% 饱足死区 | 满仓时读 0，空仓时读 1。这一条修掉了"站着饿死" |
| `thirst` | 水账本（`needs.thirst`，约 150 s 涨满，温度加成） | 由喝水清零（11-feed 写回） |
| `cold` | 气温 vs 体温中性区，体脂越高越抗冻 | climate 未落地时用日照角回退 |
| `fatigue` | `body.fatigue`（09b 按活动强度收费/清账） | 无 body 时回退到行为侧账本 |
| `fear` | 视野内捕食者距离 + 警报余辉（0.45/s 衰减） | 逃跑结束后自然回落 |
| `social` | 同种在群体半径内的数量，**社交后 35 s 满足度** | 独居物种恒为 0 |
| `curiosity` | 胆量 ×(1−饥饿)×(1−恐惧)×(饱足)×(1−习惯化) | 探完后 25 s 习惯化抑制 |
| `libido` | 已成年（stage）× 体脂富余 × 非冷却 | 老年只是冷却变长，不禁止 |

`needs`（旧字段）保留为**导出视图**：`needs.hunger/thirst/energy(=fatigue)/safety(=fear)/social`。
检视器、旧面板不用改。

## 5. 审议：只在边界或中断时打分（10-decide.js）

```
utility(动作) = Σ_驱动 权重[role][驱动] × 驱动值 × 机会质量
              × 行程时间效率            （bout / (bout + 走路秒数)）
              − 预计能量成本            （FMR/秒 × （距离/速度 + 时长），换算成 hunger 单位）
```

- **机会质量**用真实物理量：吃草的"质量"直接借 11-feed 的 Holling II 曲线（`swardQuality`），
  所以"好草地"和"啃秃的格子"在决策里差多少，和实际能吃到多少是一致的。
- **能量成本从 FMR 推**（Nagy 1999，体重决定），不是手调常数；`balance.drain` 已是 0。
- **每 tick 只做廉价中断判断**（`interruptPending`）：恐惧 >0.5、口渴 >0.85、饥饿 >0.92 才唤醒打分。
  完整打分只在 bout 边界发生。
- **迟滞**：对手必须比当前动作好 `×1.18 + 0.1` 才能翻盘；同类别不抢跑。
- **只有"要命的事"能打断承诺期**：`flee`/`drink`（优先级差 ≥2）可以立刻切；机会类（采食/捕猎）
  必须等当前 bout 的最小承诺过去。否则"到处都是草"会让任何一个 bout 都活不过 1 秒。

## 6. 执行：有长度、有条件、有承诺（10b-execution.js + 08-sim-constants.js）

| 状态 | 最小承诺 | 计划时长 | 完成条件 |
|---|---|---|---|
| `flee` | 2.5 s | 4–7 s | 恐惧 <0.3 |
| `drink` | 3 s | 4–8 s | 口渴 <0.12；或站到水边 2 s 口渴没降（放弃） |
| `forage` | 8 s | 14–26 s | 饥饿 <0.12 / 脚下吃光 / 超时 |
| `hunt`/`scavenge` | 8 / 6 s | 14–26 / 12–22 s | 到达且目标不在 / 饥饿 <0.1 / 超时 |
| `rest` | 10 s | 20–40 s | 疲劳 <0.12（同时把脚下记成 home） |
| `socialize` | 6 s | 10–18 s | 到达自己的环位或同伴够多 → 满足度置 1 |
| `explore` | 8 s | 14–26 s | 走满 3 段腿（每段同方位）或超时 |

另外三条通用规则：

1. **承诺下限对所有结束生效**（不只是被打断时）：`done && now − since < min` 时继续。
2. **走不动就放弃**：`stalledAt` 连续两个 1.3 s 窗口没有接近目标 → 结束 bout 重新审议
   （这是"沿着湖岸来回踱步"的修复）。
3. **罗盘方位** `entity.roamHeading`：跨 bout 保持，每次新 explore 只转 ±0.25 rad，
   靠地图边缘反向回中心。方向性 0.28 → 0.35 主要来自这里。

## 7. 给渲染器和检视器的字段

| 字段 | 含义 |
|---|---|
| `entity.intent` | **永远**是 8 个 id 之一，由 `state.id` 派生（渲染/旧 UI 依赖） |
| `entity.state` | `{ id, since, until, min, phase, why, score, x, y }`；`phase` ∈ `approach`/`do`/`adopted` |
| `entity.drives` | 8 个 0..1 |
| `entity.belief` | 见 §3 |
| `entity.decision` | `{ at, picked, score, why, target, alternatives[3], drives }` —— 检视器的"为什么" |
| `entity.plan` | `{ goal, steps[{x,y,act,duration}], index }` |
| `entity.handling` | 正在处理猎物/尸体（站着不动、低头吃）→ 渲染用 eat/graze 姿态 |
| `entity.cause` / `body.cause` | 死因（`starved/frozen/predation/old/injury`） |

`state.why` 取值：`hunger / thirst / fear / fatigue / social / libido / curiosity / search / resume / idle`。
（UI 若要翻译，需要 `reason.*` 词典键；`intent.*` 仍是 8 个。）

## 8. 门禁实测（seed 12345，`node tools/behaviour-probe.mjs`）

| 门禁 | 目标 | 300 s | 900 s |
|---|---|---|---|
| P2.1 rest 时间占比 | <35% | 7.2% | **2.9%** |
| P2.2 意图驻留中位数 | >10 s | 10.3 s | **13.5 s**（均值 36.2 s） |
| P2.3 方向性（净位移/路径） | >0.30 | 0.37 | **0.36** |
| P2.4 决策切换 | <12/min | 3.3 | **1.7** |
| P3.1 猎物饿死占比 | <50% | 0% | **15.1%** |
| 饿死个体最后 30 s hunger | >0.6 | — | 饥饿死亡时 hunger 中位数 **1.00**，0/238 "饱着死" |

900 s 那一列是最终 bundle（seed 12345，`--seconds 900`）。同一轮各物种出生数：
兔 478、蛙 239、鱼 180、鹿 13（狐/狼/水獭/熊 0，见 §9.2）。
同 seed 900 s 的繁殖在上一轮 bundle 里是：兔 624、蛙 227、鱼 185、鹿 37、鹭 11、鸦 3、狗鱼 3 ——
总数随草地过牧-恢复的相位波动，但每个物种都能出生，这正是 P0 要的结论。

## 9. 已知边界（不是 bug，是待拍板）

1. **结构成长的时间尺度与寿命不匹配**（09b，sim-core）：`body.M` 由实际生长的组织算，
   而生长被 1.5×FMR 的预算限制。实测 200 s 时兔子 `body.M` 中位数 **0.13**（寿命 140–240 s），
   也就是**按结构算，兔子一辈子都长不大**。本文件因此用"结构 + 年龄窗口"混合判定成年：
   过了物种成熟年龄、但身体还是小个子的个体，算**瘦小的成年**，而不是婴儿 —— 否则整个食物链绝育。
   真正的修复（成长速率/寿命/能量密度三者对齐）归 09b。
   **繁殖归零的教训**：`stage` 曾用 `maturity×2.6` 当老年线，等于把每个物种后半生判成"不可繁殖"，
   900 s 里四个物种 0 出生。现在老年线是 `0.75 × genes.lifespan`，且**老年只延长冷却，不禁止繁殖**。
2. **繁殖门槛**：旧值是 `0.7 × Emax`，而实测稳态储能只有 0.2–0.6 Emax，于是 200 s 时
   281 只兔子里只有 4 只达标、鸦 0/20、鹭 0/10、熊 0/4 —— 捕食层几乎永远不繁殖。
   sim-core 已把它改成"整胎成本 × 1.02"，上述数字随之解除；行为层只消费这个数，不再自己猜。
   新生儿的结构能量现在通过 `spawnEntity(..., { parent })` 由母体转移，世界账本的繁殖项才是真实支出。
3. **捕食层密度**是 docs/10 §4 的尺度问题（捕食生物量比 47% vs 真实 1–5%），
   行为上表现为捕食者 hunger 长期 0.5+；P3.2 目前只作为信息指标。
   行为侧能做的只有"让捕食成为过程"（handling 站立、追击有放弃规则），密度仍是 Lead 的拍板项。
4. `hunt` 的驻留中位数很长（狐 50 s、狗鱼 54 s）：捕食者在"追一只追不上的猎物"时
   会按 2.6 s 的进度窗口放弃并立刻重新决定，意图 id 不变所以合并成一段长 hunt。
   这是"看起来在打猎"的正确读数，但如果 P3 要"追击时长"指标，需要另加 `entity.decision` 计数。
