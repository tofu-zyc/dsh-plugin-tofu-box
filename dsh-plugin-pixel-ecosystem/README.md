# dsh-plugin-pixel-ecosystem（像素生态缸）

在 DeepSeek Harness 的侧边栏点一下图标，主面板就是一整块**活着的像素生态**：撒草、种树、放兔子放狼，
看它们长、吃、追、生、死。**十一个物种**连成一张跨水陆的食物网：
陆地有草 → 兔子/鹿 → 狐狸/狼/棕熊，浅水有水草、睡莲和芦苇 → 小鱼/青蛙 → 狗鱼，
**苍鹭、棕熊会站进浅水叉鱼**，水獭在水里追鱼、也能上岸歇脚；乌鸦专吃遗骸，遗骸腐烂再回肥力给草——一圈闭环。

动物带可遗传的基因（速度 / 视野 / 体型 / 代谢 / 寿命 / 繁殖率），生崽时小幅变异，所以种群会自己波动。
**动作是四帧循环**：行走是四拍侧序步（四只脚依次落地、三只脚始终着地），奔跑是带腾空相的飞奔，
熊是四拍大步，兔子和青蛙是跳，苍鹭高抬腿涉水，乌鸦扇翅，小鱼和狗鱼靠身体摆尾游。
水面有深度、焦散、涟漪和岸边泡沫，水下有摆动的草丛，捕鱼会溅起水花和气泡。

有昼夜明暗，世界自动存进浏览器本地，关掉页面再回来还在。它就是给「AI 干活、你等结果的那几分钟」摸鱼用的，
不联网、不改你的会话、不碰 Host。

## 安装

> 要接手开发这个插件？**`HANDOVER.md` 是 0.2.1 的历史交接书**（讲的是旧引擎），0.3.x 请从 [docs/00-VISION.md](docs/00-VISION.md) 开始读，再看 [docs/90-ROADMAP.md](docs/90-ROADMAP.md) 的状态总览。

包名 `dsh-plugin-pixel-ecosystem`，插件行 id 是 `pixel-ecosystem`。Client 半是手写浏览器模块，
**没有构建步骤**，仓库里是什么 npm 里就是什么。

```bash
# 1) npm（版本进入 npm 的 staged publishing 队列后，要 maintainer 批准才会出现在版本列表里）
dsh plugin --profile <你的profile> add dsh-plugin-pixel-ecosystem@0.2.3

# 2) 本插件是独立插件，**不在 tofu-box 伞包里**（清单里 dsh.umbrella: false），
#    所以没有"装伞包顺带装它"这条路，只能单独装。

# 3) 开发：从本仓库本地目录安装（link 方式，改代码不用重装）
#    必须写绝对路径：dsh plugin ... 只是转发给 profile 里的 pnpm，相对路径会被锚定到 profile 内部
dsh plugin --profile <你的profile> add "link:D:\program\dsh-plugins\dsh-plugin-pixel-ecosystem"

# 4) 追 HEAD：从 git 直装（未发版或想看最新代码时）
dsh plugin --profile <你的profile> add "git+https://github.com/tofu-zyc/dsh-plugin-tofu-box.git#path:dsh-plugin-pixel-ecosystem"
```

在当前会话里用 `plugin_manager` 装（会让该 profile 的所有会话生效）：

```
plugin_manager install_bundle target = D:\program\dsh-plugins\dsh-plugin-pixel-ecosystem
```

手工维护 profile 的 `cordis.patch.yml` 时，等价写法是：

```yaml
- insert:
    - id: pixel-ecosystem
      name: dsh-plugin-pixel-ecosystem
```

要点：

- **新装的 Client 模块要刷新一次页面才会加载**；刷新后侧边栏多一枚像素图标，点它进主面板，
  点「回到对话」收回会话。
- `link:` 装法省掉的是「拷贝」，不是「重载」——改完 `client.js` 仍要重启 dsh。
  改了 `package.json` / `dsh.bundle` 这类结构，得把上面的 `add` 重跑一次。
- 建议在**隔离 profile** 里装：本仓库的规矩是只用 `rc-dev` / `alpha-dev` 两个测试 profile
  （见 [`docs/TESTING-PROFILES.md`](../docs/TESTING-PROFILES.md)），**不要**装进你日常用的
  `desktop` profile。

## 怎么玩

世界 **512 × 400 格**（`createWorld` 把每边夹到 ≤ 512，所以默认值 640 实际落在 512）。地形
`水 / 沙 / 土 / 草地 / 石头` 由种子程序化生成。实测五个种子（777 / 31 / 4242 / 1 / 99）：
**约 17.7% 水、2.7% 沙、11.5% 土、67% 草地、1.0% 石头**；开局 483 只动物、560–585 株植物
（树/灌木目标 430 株，另撒约 95 片睡莲 + 约 60 丛芦苇，播种/拥挤失败会少几株）。

### 头部与面板控制

| 控件 | 做什么 | locale key |
| --- | --- | --- |
| 暂停 / 继续 | 冻结或恢复模拟（暂停时仍可放置、缩放、观察、单步） | `action.pause`、`action.play` |
| 1× / 2× / 4× / 8× | 时间倍速，默认 **2×**。1 天 = 120 秒（1× 下） | `speed.1` … `speed.8` |

| 回到对话 | 收起主面板、回到会话（只在拿得到 layout 服务时出现） | `action.back` |

## 生态机制

### 物种与食物网

| id | 中文 | 介质 | 角色 | 吃什么 | 被谁吃 | 备注 |

生产者有六种：草（陆地逐格生物量场）、水草（水下逐格生物量场）、树、灌木，以及
**睡莲**（浮在浅水，把脚下的水喂肥，鱼就聚过来吃）和**芦苇**（长在岸边沙地上，给岸线一个看得见的边）。

### 一圈闭环

```
草 ──→ 兔子 ──→ 狐狸 / 狼 / 棕熊
 │        │
 └──────→ 鹿 ──────→ 狼 / 棕熊

水草 / 睡莲 ──→ 小鱼 ──→ 狗鱼
   │             │  ├──→ 苍鹭   ←── 站进浅水叉鱼
   │             │  ├──→ 水獭   ←── 潜进水里追
   │             │  └──→ 棕熊   ←── 下水捞鱼
   └──→ 青蛙 ────┘  └──→ 苍鹭 / 水獭 / 狗鱼

（一切死亡）──→ 遗骸 ──→ 乌鸦（专属）/ 狐狸 / 狼 / 狗鱼 / 苍鹭 / 水獭 / 棕熊 吃
                   └──→ 腐烂（42 秒）→ 肥力 ↑ → 草 / 水草长得更好 ──┐
                                                                └──→ 回到最上面
```

**跨水陆的捕食**是 0.2.0 的重点：苍鹭和棕熊能站进浅水（`wade`），所以鱼第一次有了陆地上的天敌；
水獭反过来能上岸（`amphibious`）。能不能下水由**水深**决定——`computeHydrology` 把"离岸距离 ÷ 16"
存成 `world.depth`，`canStand` 只允许涉水物种站在 `depth < 0.34`（约离岸 5 格内）的水格里，
所以它们只在水边活动，不会走进湖心。涉水时速度 ×0.62；水獭上岸 ×0.72。

- **谁吃谁**只由物种表里的 `prey` 决定且**有序**（狼先找鹿，找不到才回头吃兔子）：
  狐狸吃不到鹿，狗鱼只吃小鱼和青蛙，乌鸦只吃尸体。同一个 tick 里同一具猎物不会被吃两次。
- **捕食成功**靠 `balance.catchRadius`（1.15–2.4 格），吃到的是
  `猎物 meat × 本物种 meatGain`（狐狸 3.1、狗鱼 2.8、苍鹭 2.5、狼和水獭 2.4、棕熊 2.2）——
  一只兔子 `meat` 只有 18，没有这个系数捕食者每天得杀一只才活得下去。
- **能量**：吃饱（能量过 `breedEnergy`）+ 成年 + 繁殖冷却结束 → 生崽；能量归零、或超过寿命 → 死亡。
  被吃也算死亡，走同一条路径（`killEntity`）：移除个体 + 掉一具遗骸（能量 = `meat × 0.8`）。
- **遗骸**：腐烂过程中给周围 3×3 加肥（水里加 `waterFertility`，陆地加 `fertility`），
  所以「死」在这缸里是养分，不是删除。
- **介质是硬边界**：陆地物种进水或进岩会被挡住（沿边滑），水生物种出不了水，只有乌鸦无视地形。
- **昼与夜**：1 天 = 120 秒（1× 下），画布上有昼夜明暗和晨昏暖色；每个物种有自己的
  `activity` 四段倍率（晨/昼/昏/夜），同时作用于移动速度和休息倾向。**夜里草长得慢**。
- **自动保存**：每 30 秒 + 页面卸载时写一次，key 是 `dsh-pixel-ecosystem:v1`；
  「新世界」会换种子重开一缸。

### 基因与变异

每只动物带六项基因：速度、视野、体型、代谢、寿命、繁殖率。生崽时子代继承父母的基因并
**小幅漂移（±7%）**，有 5% 的概率是大幅跳变（±20%），再夹回该物种的基因区间。于是：
跑得快的更容易吃到东西、看得远的更容易先发现猎手、体型大的更能扛饿也更慢——
这些权衡是种群自己波动而不是数值崩盘的来源。点开任意一只生物就能看到这六条基因条。

### 平衡契约（不是对任何世界的承诺）

这是**会波动的**世界，不是稳态世界：兔子爆到 600 只、把草啃光、狐狸跟着饿死一批，属于正常剧情。
固定种子 soak（20 000 tick = 2 000 世界秒 ≈ 16.7 个 1× 天）看守的是三条底线，也是
`tests/balance.test.mjs` 每次都会重新验证的三条：

1. **不许永久灭绝**：某个物种可以跌到很低甚至归零，但 `MAX_ZERO_CHECKPOINTS = 2`
   （20 个 1000-tick 检查点里最多 2 个读数为 0）——因为「移民」每 25–45 秒检查一次，
   低于该物种的 `minimum` 就从图里补 4–8 只。soak 结束时每个物种还必须 > 0。
2. **每条链都得活着**：每个物种在整个 soak 里必须达到过自己的 `VIABLE_PEAK`
   （兔 120 / 鹿 22 / 狐 12 / 狼 5 / 乌鸦 18 / 鱼 55 / 狗鱼 5 / 苍鹭 5 / 水獭 5 / 熊 3 / 青蛙 20），
   证明它的食物链真的成立，而不只是数字没归零。
3. **不许失控**：任何物种都不许越过自己的 `cap`（兔 400 / 鹿 260 / 狐 170 / 狼 90 / 乌鸦 220 /
   鱼 170 / 狗鱼 70 / 苍鹭 60 / 水獭 70 / 熊 40 / 青蛙 160），否则一代之后会把别人全饿死。
   （0.2.2 把兔 620→400、鱼 520→170、青蛙 420→160：高倍缩放下那三个数字会叠成一堵"动物墙"，看不出个体。）
   另有草/水草覆盖 ≥ 各自地形的 3%，以及吞吐 > 80 tick/s（8× 的预算）。

> 0.2.0 修掉的两个真问题（有数据支撑，不是拍脑袋）：

> 所以整个捕食层 Intent 里 `explore` 占 60%+、平均饥饿 0.8——现在捕食者有 `huntReach`（视野 ×2.6 的嗅觉）；
> ② 一次捕杀只给「猎物尸体价值」那么多能量（狐狸吃一只兔子只值 18 点，20 秒就烧完）——现在有 `meatGain`。
> 同理，食草动物饿了会把搜索半径放大到 2.4 倍，否则它们会站在草地上饿死：`findFlora` 只做 12 次随机采样，
> 采样半径 = `视野 × (饥饿 > 0.4 ? 2.4 : 1)`。

> 当前实测的意图分布（三个种子平均）：食草层 `rest` 60–80% / `forage` 14–30%；
> 捕食层 `explore` 27–50% / `hunt` 13–41%；乌鸦 `scavenge` 37–47%。
> 捕食层的平均饥饿（0.58–0.90）仍明显高于食草层（0.12–0.27），这是 0.2.0 还没收干净的地方。

你自己手画的极端地形（全石头、全水、把猎手全堆在角落）里灭绝仍然是正常结果——移民只会补到
`minimum`，补不回一个被彻底破坏的生态。

## 它是怎么实现的

- **两个 slot，都是加法**：`sidebar.panellist` 注册一枚 `id: 'pixel-ecosystem'` 的图标，
  `main` 注册 `key: 'pixel-ecosystem'` 的面板。两个 id 是同一个字符串是故意的——侧边栏按钮打开的就是
  这个 key 的主面板。插入用的 `cordis.patch.yml` 只有一条 `insert`，不覆盖、不禁用任何官方行。
- **单文件 Client bundle**：`client.js` 一个文件装下引擎 + 渲染 + 面板 UI，手写浏览器模块，免构建。
  引擎是**纯函数层**（不碰 DOM、不读系统时钟，时间靠 `dt` 传进来），通过
  `module.exports.__engine` 导出，Node 里能直接跑几万 tick 做测试。
- **混合分辨率渲染**：地面画进「每格 1 像素」的小缓冲 `Uint32Array`（`paintView`），
  `putImageData` 到离屏 canvas 后用 `drawImage` **最近邻放大**到显示 canvas；
  **动物不画进小缓冲**，而是从图集以显示分辨率画（`drawAtlasAnimals`）。地面按全分辨率渲染跑不动
  （512×400 × 6² ≈ 740 万像素/帧），动物则要清晰——这是刻意的分层。
- **水面**（`waterColor`）：先按 `world.depth` 三层混色（`waterSurface → waterShallow → waterMid → waterDeep`），
  再叠**焦散**——三项正弦相乘（两项的乘积是格子，会在整片湖上印出网状纹理，第三项打散对称性）；
  然后一条更细的涟漪带，最后按离岸距离三档叠泡沫（`d<0.055` 强泡沫、`d<0.11` 中、`d<0.16` 且噪声高则有碎沫），
  岸线因此是"画出来的边"而不是"颜色变了"。
- **草地**（`paintGround`）：8 级 `GRASS_RAMP` 打底，叠两个尺度的变化——格级摆动（`SWAY` 表，
  按 tick 位移，看起来像草叶在动）和一个**慢速 patch 场**
  （`sin(x·0.055+0.7) · sin(y·0.043−1.1) · 7` 的整数色阶偏移，做出干/润地块）；
  厚草格上有概率出现亮草叶和四色小花，裸土格上会出现土色斑。
- **植物与影子**（`paintPlants` / `shadeEllipse`）：植物按 y 排序（远的先画，冠层正确遮挡），
  每株按 `id % 3` 取三档明暗（一片全同的印章看起来像壁纸），`foliage < 0.35` 再压暗；
  除睡莲外都在脚下打一个椭圆软阴影（`shadeEllipse` 两档衰减 0.86 / 0.72——单档的椭圆放大后读成矩形）。
- **动物的影子与步态**：每只动物在脚下画一个 `rgba(10,22,14,0.22)` 的椭圆阴影（没有它精灵像贴纸）；
  步态相位 `entity.gait` 是**按走过的距离累加**的（每格 `ATLAS_GAIT[species]` 个循环），
  所以慢的动物迈小步、逃跑的动物迈快步，不需要任何速度 if 链。跑动帧按 `gait` 取，
  idle/walk 帧按世界时间取。奔跑时还有 ±7% 格高的上下起伏和 ±4% 的拉伸挤压。
- **帧角色**（`atlasFrameRole`）：`fleeing` → run；本 tick 位移 < 0.06 格 → idle；
  否则**低于自己最高速（`genes.speed`）的 62% 走 walk，否则 run**；乌鸦/鱼/狗鱼没有 walk 槽位，直接 run。
- **环境光**：昼夜是在整帧上叠两层 `fillRect`——夜色最多 50%（`(1-light)×0.55`）的深蓝，
  加晨昏（`phase` 0.17–0.30 与 0.71–0.85）最多 16–18% 的暖橙。
- **持久化**：`localStorage`，key `dsh-pixel-ecosystem:v1`，每 30 秒 + `beforeunload` 写一次；
  地形和两张生产场按字节量化（每格 1 字节 base64），水文（`depth`/`moisture`）不存、读档时重算；
  读档失败（版本不符 / 坏数据 / 配额满）静默丢弃，开一缸新的。
- **没有 Host 代码，这是有意的**：`index.js` 的 `apply()` 是空的，不注册 service、不注册投影、
  不注册工具、不起定时器。理由有两条——浏览器里的 rAF 循环没法被 Host 驱动；游戏的存档
  **不该折进 Session 日志**（世界状态不是会话真相，重放/分叉/fork 都不该带上它）。
- 面板文字全部走 locale，颜色只用 `--dsw-alias-*` token（像素画布内部除外，那是美术）。

```js
// Client 的注入与两个席位
ctx.slots.inject('sidebar.panellist', () => ctx.slots.register(
  { name: 'sidebar.panellist', id: 'pixel-ecosystem', order: 20, label: () => t('panel.title') }, PanelIcon))
ctx.slots.inject('main', () => ctx.slots.register(
  { name: 'main', key: 'pixel-ecosystem' }, props => h(Panel, { ...props, store, locale })))
```

### 图集与美术管线

图集是**代码生成的像素画**，不是手绘素材：`assets/atlas.png` 一张 **512 × 767** 的 PNG，
8 列 × 13 行，每格 **64 × 59**，脚踩在 `baseline = 52` 上；当前构建共 **98 个动画帧**
（11 个物种：idle 2 帧 + walk 4 帧 + run 4 帧，乌鸦/鱼/狗鱼没有 walk）。

| 文件 | 做什么 |
| --- | --- |
| `tools/build-atlas.mjs` | 把每种角色的每一帧按 `{id, role, index}` 顺序排进图集，写 `assets/atlas.png` 与 `assets/atlas.json`（几何 + 槽位表 + 视觉尺寸 + 步态系数）；`--preview` 另写 `.scratch/atlas-preview.png` 4× 检查表，并始终写 `.scratch/atlas-base64.txt` |
| `tools/embed-atlas.mjs` | 从 `atlas.json` **重新生成** `client.js` 里的 `ATLAS` / `ATLAS_SLOTS` / `ATLAS_SIZE` / `ATLAS_GAIT` 四个常量，并把 PNG 以 base64 写进 `SPRITE_ATLAS_PNG`（单文件发布的代价） |
| `tools/patch-region.mjs` | 按「起始标记字符串 → 结束标记字符串」替换文件里的一段（`patch-region <file> <startMarker> <endMarker> <replacementFile>`），给这种几千行单文件做区域替换用 |
| `tools/pixel/ai_rig.py` | **拆件**：把 AI 出的图色键、反推逻辑像素网格、降采样、切成躯干+四腿+头部，写 `assets/models/<id>.json`，同时输出 `-pixels.png`（降采样结果）与 `-rig.png`（部件染色图）供肉眼核对 |
| `tools/pixel/rig.mjs` | **摆帧**：读模型 JSON，按步态相位绕枢轴旋转每条腿（逆映射，避免细腿出洞）、起伏躯干、摆动头部，产出图集单元格 |
| `tools/pixel/png.mjs` | 最小 PNG 编码器（无依赖） |
| `tools/pixel/raster.mjs` | 当前构建用的材质式光栅原语：`set` / `ellipse` / `rect` / `limb` / `polygon` / `blitInto`，外加 `clipped(box, paint)` 裁剪框；形状只写**材质名**不写颜色，方便整体换色 |
| `assets/atlas.json` | `{ cellWidth, cellHeight, columns, baseline, slots, display, gait }`——图集的机器可读契约，`embed-atlas.mjs` 的输入 |

> 帧内容的生成分两条路：**狼/鹿/狐/熊/兔/水獭** 走「AI 出图 → `ai_rig.py` 拆件 → `rig.mjs` 摆帧」
> （每个物种两套模型：站立 + 飞奔）；**乌鸦/苍鹭/鱼/狗鱼/青蛙** 仍是 `tools/pixel/creatures.mjs` 的程序化模型。
> `build-atlas.mjs` 里的 `RIG_TARGET` 表决定谁走哪条路，以及它 6× 下的屏幕宽度。
> 完整流程与加新物种的步骤见 [HANDOVER.md](HANDOVER.md) §12。

├── HANDOVER.md          # 交接：状态、代码地图、验证方式、已知缺陷、下一步

├── assets/              # atlas.png / atlas.json / models/*.json（图集与拆件模型的源文件）—— 不进 npm 包
├── tools/               # 美术流水线：pixel/{ai_rig.py,rig.mjs,creatures.mjs,...} + build/embed-atlas.mjs —— 不进 npm 包

`package.json` 的 `files` 只放 `index.js`、`client.js`、`cordis.patch.yml`、`locale/*.json`、
`icon.svg`、`README.md`——**`assets/`、`tools/`、`tests/`、DESIGN.md、HANDOVER.md 都不发布**。

### 浏览器里的两个验证页（`file://` 直接打开即可，无服务器）

| `seed` | 777 | 世界种子 |
| `ticks` | 4000 | 先在后台跑多少 tick 再截图 |
| `cells` | 3 | 物种表每格的放大倍率 |
| `clock` | — | `noon` / `dusk`，把时间拨到正午或黄昏看光照 |
| `focus` | — | `hunt`：在浅水区现场撒鱼/青蛙 + 苍鹭/棕熊/水獭，摆出跨水陆捕食的镜头 |

这是单测做不到的那一步：证明图集帧在渲染循环里真的在换。

`tests/species-sheet.html?<参数>` —— 只画图集，用来肉眼验帧：

## 0.2.2 修复了什么

这一版有两个来源：美术换代，和一个用户在真实浏览器里点出来的 bug 清单。

### 美术：AI 出图 → 拆件成可编辑模型

之前的四足动物是用椭圆/多边形现拼的骨架，体态一直不像。现在改成三段流水线（详见 [HANDOVER.md](HANDOVER.md) §12）：

1. `generate_image` 出一张「品红底、正侧视、四腿着地」的像素图；
2. `tools/pixel/ai_rig.py` 色键、反推出生成图的**真实逻辑像素网格**、降采样、拆成躯干+四腿+头部；
3. `tools/pixel/rig.mjs` 绕枢轴转腿、起伏躯干、摆动头部，输出 idle/walk/run 帧。

狼 / 鹿 / 狐 / 熊 / 兔 / 水獭 各有**站立**和**飞奔**两套模型，run 帧用的是真正腾空的疾驰姿态。
乌鸦 / 苍鹭 / 鱼 / 狗鱼 / 青蛙 仍是程序化模型。

### 四个 bug

| 现象 | 真正的原因 | 修法 |
| --- | --- | --- |
| 动物在水陆边界一直打转 | `moveToward` 撞墙时把朝向**随机重设**：朝目标走→被水挡住→随机转身→再朝目标走 | 按 `[0, ±0.5, ±1.0, ±1.6, ±2.4]` 弧度依次绕行，朝向跟随实际位移；全方向受阻 0.3 s 后在附近换目标 |
| 鱼像飘在空中 | 所有动物都画地面投影，鱼也带一个椭圆阴影 | 按栖息地分开：水生改画淡蓝**涟漪环**并上移 2 px |
| 水草放不下去 | `weed` 只在 `terrain === WATER` 时写入，点草地/沙地**静默失败** | 岸边沙地/泥地也能种，并在 `weed > 0.3` 时与绿色混合渲染，种下立刻可见 |
| 奔跑和行走没区别 | ① 渲染层用 `moved/TICK` 比 `genes.speed × 0.62`，而 `moved` 含昼夜活动系数 → 白天几乎天天在"跑"；② 追逐/逃跑倍率只有 1.06–1.15，速度本来就差不多 | ① 改由引擎判定 `entity.running = pace >= 1.25`；② 逃跑 1.35–1.7 → **1.85–2.15**、捕猎 0.9–1.15 → **1.25–1.55**；③ 跑动步频 ×1.45 |

顺带两个修：**生命工具条**改由 `SPECIES_IDS` 生成（此前 11 项里缺苍鹭/水獭/棕熊/青蛙，玩家根本放不出来，
只能靠移民出生），并加了"每个物种都必须在 `LIFE_TOOLS` 里"的回归测试；
**植物与动物合并成一个按 y 排序的深度通道**，树这才真的能遮住动物（以前动物永远压在整个森林上）。

实测（seed 777 / 31，2400 tick 采样）：稳态下约 **40 只在跑、200 只在走、449 只在休息**；
贴水边 1 格内的陆生动物每帧 70–85 只，其中**连续 120 tick 位移 < 1.2 格的：0 只**——修之前它们就在原地转圈。

## 已知限制

- **0.1.0 已提交 npm，等待 maintainer 批准**（staged publishing）；在此之前用 `link:` 或 git 直装。
  本插件不进 `tofu-box` 伞包。
- 只声明了 `platform: web`：浏览器里的视觉确认还没做（见上面「测试」）；桌面端（Electron）、
  Linux / macOS 都没有验证过。
- 世界只活在**当前浏览器的 localStorage** 里：换浏览器、清站点数据、换 profile 就是新世界；
  它也不进 Session 日志，所以没有跨设备/跨会话同步，也没有「存档分享」。**一张存档一个世界**：
  「新世界」会覆盖旧档。
- **读档不恢复心理状态**：`serializeWorld` 只存位置、能量、年龄、代数、冷却和基因；
  `needs` / `intent` / `stage` / 群体锚点读档后回到默认值（饥饿 0.32、意图下一 tick 重算）。
  所以刷新页面后所有动物会重新"想一遍"。
- 硬上限：动物 3600、树/灌木/睡莲/芦苇 1150、遗骸 260。到顶只禁止新增，不杀已经存在的个体；
  玩家手动放置的上限放宽到该物种 `cap × 1.4`。
- 世界每边最多 512 格（`createWorld` 里的夹取）；默认 512 × 400 = 204 800 格并在这个尺寸上调过参，
  更大的世界没调过，掉帧或生态崩掉都正常。
- 平衡靠固定种子 soak 看守；极端地形里灭绝是允许发生的结果（见上面「平衡契约」）。
- 坏档静默丢弃：`version` 不符或数据坏了就直接开新世界，不会告诉你丢了什么。
- 明确不做：联网、多人、存档分享、Host 端工具、文明/建筑、天气、音效。
- 插件由 AI 实现，肯定还有没抓出来的 bug。
